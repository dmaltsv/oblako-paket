# Обновление пакета

Пакет живёт своим маленьким репозиторием и обновляется отдельно от сервера,
поэтому отстать он может сам собой. Отстал — сервер и скрипты скажут об этом
прямо: «сначала обновите пакет».

**Все команды ниже написаны от папки команд** — той, где лежит `meeting.py`. Её
точный путь на этой машине назван в подключении скилла.

**Ничего личного обновление не трогает:** файл настроек `.env` и папка `Разборы`
в репозиторий не входят, обновление их не видит и не переписывает. Скажи это
человеку сразу — это первое, о чём он спросит.

## Шаг 1. Что стоит сейчас

```
python setup_check.py --offline
```

Первая строка называет текущую версию. Запомни её — в конце сравнишь.

## Шаг 2. Убедиться, что обновляем пакет, а не проект

```
git -C "<папка команд>" rev-parse --show-toplevel
```

Ответ **совпал с папкой команд** — это клон пакета, иди дальше.

Ответ **выше папки команд** — ты в репозитории проекта Oblako, а не в пакете
(здесь скрипты лежат в подпапке `Пакет/`). Обновлять его этой командой нельзя:
`git pull` утянул бы весь проект, а не пакет. Скажи это человеку и остановись —
он разработчик и знает, что делать.

## Шаг 3. Забрать свежее

```
git -C "<папка команд>" pull --ff-only
```

Что может ответить:

- **обновилось** — иди дальше;
- **`not a git repository`** — папку принесли архивом, а не клонировали. Не
  тупик: сделай её обновляемой на месте (шаг 2 инструкции `ustanovka`, «папку
  принесли архивом») и вернись сюда. Личное при этом цело: `.env` и `Разборы/` в
  репозиторий не входят;
- **есть местные правки** (`Your local changes…`) — человек что-то менял в
  скриптах. Не отбрасывай их молча: покажи `git -C "<папка>" status`, спроси и
  действуй по его слову;
- **нет доступа или сети** — покажи человеку, что ответил `git`. Хранилище пакета
  открытое, аккаунт для обновления не нужен, поэтому отказ означает сеть,
  прокси или опечатку в адресе.

## Шаг 4. «Мои встречи» — завести, если их ещё нет

Со сборки 1.13 у человека появляются **«Мои встречи»** — его личный репозиторий
расшифровок: закрытый репозиторий в его собственном аккаунте GitHub, куда ложатся
разговоры 1:1 и встречи, которые ни к отделу, ни к совету не относятся. На компьютере, где
пакет ставили раньше, его нет — заводит его этот шаг, и **только он**: у мастера
установки свой путь, а больше адрес на компьютер не дописывает никто.

**Шаг стоит после шага 3 не случайно — не переставляй его выше.** Корневым
репозиторием `oblako-lichnoe` считает только пакет 1.13: для сборки 1.12 всё,
кроме `sovet`, — репозиторий отделов, и текст она положила бы внутрь
`Отделы/<Отдел>/`, а не от корня. Сначала свежий пакет, потом адрес.

Посмотри, есть ли адрес уже (строка `OBLAKO_LIBRARY_URLS` в `.env` рядом с
командами). **Есть `oblako-lichnoe`** — шаг закрыт, ничего не трогай и иди
дальше. Нет — сделай три вещи:

```
gh repo create oblako-lichnoe --private
```

**Ответ «already exists»** — репозиторий уже заведён, это не ошибка: бери его
адрес как есть. **Ответ про вход** (`gh auth login`) — человек не входил в
GitHub с этой машины: пройди с ним пункт 3 шага 9 инструкции `ustanovka` и
вернись сюда.

Затем **допиши адрес** в конец строки `OBLAKO_LIBRARY_URLS` через `;` (остальные
адреса не трогай, порядок не меняй):

```
OBLAKO_LIBRARY_URLS=<что было>;https://github.com/<его аккаунт>/oblako-lichnoe
```

И **склонируй**:

```
git clone https://github.com/<его аккаунт>/oblako-lichnoe "<папка команд>/Библиотека/oblako-lichnoe"
```

Скажи человеку простыми словами: это его личная папка, общие репозитории про неё
не знают, и доступа туда нет ни у кого, включая владельца системы.

**Автомат подключён?** (`OBLAKO_ROUTINE_ID` в `.env`) — тогда адрес нужен ещё и
рутине в облаке, иначе она положить туда ничего не сможет. Сделать это отсюда
нельзя: скажи человеку «скажи агенту «подключи автомат»» — мастер добавит адрес
в репозитории рутины и в её окружение.

## Шаг 5. Переподключить команды

Инструкции могли измениться, а указатели на них лежат отдельно:

```
python install_skills.py
```

Затем **перезапусти клиента** (закрыть и открыть заново) — иначе он держит
старые инструкции в памяти.

## Шаг 6. Проверить

```
python setup_check.py
```

Смотри три строки:

- **версия** в шапке — сравни с шагом 1 и скажи человеку, с какой на какую
  перешли (не изменилась — значит уже было свежее, так тоже бывает);
- **версия формата** — она и есть причина, по которой обновлялись. «Сервер и
  пакет сходятся» означает, что разбор снова сдаётся;
- **«Библиотека доступна»** — в перечне имён должен быть `oblako-lichnoe`, если
  шаг 4 его заводил. Нет — вернись к шагу 4 и посмотри, что ответил `git clone`.

Осталось «сервер ушёл вперёд» — обновление не доехало: вернись к шагу 3 и
покажи человеку, что ответил `git`.

Появилось «отстал сервер» — теперь наоборот, отстал сервер. Коллега тут
бессилен: обновляет его владелец системы, и сказать надо ему.
